# Использование ИИ

## Инструменты и делегированные задачи

Claude Code (модель Claude Opus 5.5) в терминале с доступом к репозиторию,
Docker и `gh`. Агенту были делегированы:

- разбор «Задача.docx» и создание GitHub Issues #1–#8;
- диагностика сборки Docker-образа;
- воспроизведение ошибок, исправления, тесты и этот отчёт.

Задачи выполнялись по порядку: #1 → #2 → #3 → #5 → #4 → #6 → #7 → #8,
по одному коммиту на Issue.

## Один существенный пример

**Задача, контекст и ограничения.** Issue #5: при быстром переключении
карточку подменяют поздние ответы загрузки и сохранения. Ограничения из ТЗ:
React 18 без новых библиотек в приложении; задержки API не убирать;
решение должно работать с задержками и без них; поздний ответ сохранения
предыдущей заявки не должен подменять текущую карточку.

**Смысл запроса.** «Сначала воспроизведи гонку автоматическим тестом, который
падает на исходном коде. Затем исправь `TicketPanel.jsx` так, чтобы ответы
загрузки и сохранения применялись только к выбранной заявке, а список
обновлялся всегда».

**Предложение модели и изменение в коде.** Тест подменяет `fetch`
«сервером», которому тест отвечает вручную и в нужном порядке
(`frontend/src/testServer.js`). Исправление в `TicketPanel.jsx`:

- `AbortController` в cleanup эффекта загрузки;
- сброс карточки при смене `selectedId`;
- `currentId` (`useRef`) для сверки id после ответа POST;
- `savingRef` против двойного клика до перерисовки.

## Проверка результата

- Тесты гонок запущены на исходном `TicketPanel.jsx`: 2 из 7 упали.
  После исправления все прошли. Затем добавлены тесты `App` (обновление
  списка) и тесты ошибок, сейчас проходят все 9.
- API-тесты прогнаны на исходном backend из первого коммита (10 из 15 упали)
  и на исправленном (все прошли). Прогон выполнен и с `DEMO_LATENCY=1`,
  и с `DEMO_LATENCY=0`.
- Отдельный скрипт с 20 раундами параллельных изменений показал, что история
  при `FOR UPDATE` остаётся согласованной.

**Исправлено или отклонено:**

- В первом варианте теста поздний ответ для #101 отправлялся с
  `.catch(() => {})`. Это скрывало бы падение проверки, если бы запрос
  не был отменён. Заменено на явную ветку: если запрос не отменён,
  тест отвечает на него и проверяет, что карточка не подменилась.
- `npm install` переформатировал `package.json` в многострочный вид и раздул
  diff. Исходный компактный формат восстановлен, версии закреплены точно,
  как у остальных зависимостей.
- Удалить задержки API или ставить `key` на компонент для «перемонтирования»
  отказались. ТЗ прямо запрещает первое, а второе не решает гонку ответа
  сохранения.
